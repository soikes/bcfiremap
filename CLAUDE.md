# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

- **React 19** with `react-dom`, web only
- **mise**: installs the dev tools at the versions in `mise.toml` (Bun, flyctl and the Docker CLI), locked with checksums in `mise.lock` for macOS arm64 and Linux x64; loads the env files; and runs the project tasks. After changing a version in `mise.toml`, run `mise lock --platform macos-arm64,linux-x64` and commit both files. CI installs from the lockfile with `jdx/mise-action`.
- **Bun 1.3.10**: package manager, runtime, bundler, dev server and test runner (use `bun` for everything, never `npm` or `yarn`). The same version is pinned in `mise.toml`, the `Dockerfile` and `@types/bun`; change them together.
- **MapLibre**: `react-map-gl/maplibre` + `maplibre-gl` (pinned 5.24.1); OSM Bright basemap style on OpenFreeMap tiles
- **TypeScript**: strict mode

## Commands

Run project tasks through mise (`mise tasks ls` lists them); it uses the locked tool versions and loads the env files:

```sh
mise install --locked   # install the tools exactly as mise.lock records them
mise run dev            # build the production image and run it in Docker (nginx + Bun) on http://localhost:8080; Ctrl+C stops it
mise run dev:hot        # Bun dev server on http://localhost:8080 with hot reload, plus the API (same port as `mise run dev`, so run only one; `PORT` overrides it)
mise run check          # typecheck and test (what CI runs)
mise run test           # bun test with happy-dom and React Testing Library
mise run typecheck      # tsc --noEmit
mise run boundaries     # fetch the CRD's municipal boundaries from BC's ABMS service into data/boundaries (dev only; the app never fetches them)
mise run build          # build the image on Fly's remote builder without deploying
mise run deploy         # build on Fly and deploy (asks first; never run without being asked)
```

`mise run dev` needs a running Docker daemon, which each developer brings (Docker Desktop, colima, OrbStack, ...); mise only provides the Docker CLI. The underlying `bun run dev|build|test|typecheck|boundaries` scripts in `package.json` still work on their own.

Env precedence is the same with and without mise: a shell variable wins, then `.env`, then `.env.template`. mise loads both files under `[env]`, which would normally override the shell, so each overridable variable also gets a line in `mise.toml` that prefers the shell's value (see `PUBLIC_EXAMPLE_BANS`); add one for each new variable.

## Architecture

- `web/index.html` — page shell; Bun bundles `web/main.tsx` and `web/index.css` from it
- `web/main.tsx` — renders `App` into `#root`
- `server/dev.ts` — dev entry: `Bun.serve` with the page (an HTML import, bundled on the fly with hot reload) and the API routes
- `server/index.ts` — production entry: `Bun.serve` on `127.0.0.1` with only the API routes; nginx serves the page
- `server/api.ts` — starts the server collectors and returns the `/api/bans` route, shared by both entries; the route answers once every server source has had its first try, so the browser needs to ask only once
- `server/banStore.ts` — loads every server collector on start, with retries, then again on the collector's own `refetchIntervalMs` if it sets one (none do yet: the standing bans are built from stored data, so they load once), and tries a source that failed again within 10 minutes; a failed refresh keeps the last good data. Keeps the data per source in memory only, and builds the `/api/bans` response. Only the server re-fetches: browser collectors ignore `refetchIntervalMs`, and the page asks `/api/bans` once
- `components/App.tsx` — root component; provides the react-query client, owns the selected-location state and composes the map layers and `BanPanel`
- `components/BaseMap.tsx` — full-size MapLibre map that reports clicks as a `LatLng`; it opens fitted to the Capital Regional District's municipalities (`INITIAL_VIEW` in `constants/map.ts`, a bounding box so it suits any screen size), for demos, since that is where the local rules are
- `components/FireZones.tsx`, `BanPolygons.tsx` (one fill and one outline layer, coloured by permission), `SelectedPin.tsx` — map layers built from react-map-gl's `Source` and `Layer`
- `components/LocationSearch.tsx` — search box and "My location" button over the map (top left on wide screens; centred below 768px, where an empty spacer the spinner's width balances the spinner). A search goes to Nominatim (see Place search): one match is chosen straight away, several are listed, and a "not found" or failure message (a `Toast`) hides itself after 6 seconds. Reports the chosen place as a `LatLng`; `App` selects it and asks `MapFocus` to move
- `components/MapFocus.tsx` — draws nothing; each time its `target` is a new object it fits the map to the bans covering the point (`fitBounds`, padded for the results panel, `maxZoom` 12), or flies to the point at zoom 12 when no ban covers it. Map taps never move the camera. Its `bans` are read when `target` changes, so bans that finish loading afterwards don't move the map again
- `components/BanPanel.tsx`, `BanCard.tsx` — results panel (centred and width-limited on wide screens); lists the bans at the tapped point, strictest first (each card names its activity, e.g. "Beach fires", followed by what it permits today: red ✕ Prohibited, yellow ✎ By permit only, yellow ! Allowed with conditions or green ✓ Allowed; the panel headline counts the rules that aren't "allowed" as restrictions) plus the status, coverage and attribution of each source that supplied one of those bans or failed (sources still loading aren't listed; the headline says "Loading ban data…" while nothing has been found yet), with a warning when a source failed
- `components/LoadSpinner.tsx`, `Toast.tsx` — a small graphic-only spinner next to the search box, spinning while any source is still `pending` (its first request or a retry of it; it keeps its space when idle so the search box doesn't change width), and the pale yellow message box shared by the search messages and the failed-load message
- `components/Disclaimer.tsx` — a short "work in progress, for informational purposes only, check with your municipality or fire department" notice centred at the bottom of the map. It watches MapLibre's attribution (a `MutationObserver` on the map's classes): while the attribution shows its text the notice sits just above it, and once it collapses to its "i" button (MapLibre's compact mode, open on load and closed by the first drag) the notice drops to the bottom edge beside the button. It is hidden while the results panel is open (`.app:has(.ban-panel)` in `App.css`)
- `components/ErrorBoundary.tsx` — catches render errors in the ban layers and the panel so the base map keeps working; tries again when its `resetKey` changes
- `collectors/` — one `Collector` per data source (`types/collector.ts`): `collect()` fetches and normalizes to `FireBan[]`. `constants/browser.ts` lists the collectors that run in each visitor's browser, `constants/server.ts` the ones the server runs (see Fire bans for which goes where); keep them in separate files so each bundle only contains its own collectors. `provincial.ts` is the BC Wildfire Service ArcGIS feed, `example.ts` is fake dev data (made-up bans shaped like the real Kamloops Fire Centre, whose zones are merged into one outline with `polygon-clipping`, and the Penticton Fire Zone, fetched at runtime from the zones service, plus hand-drawn local ones; the real collector does no merging and uses each row's own polygon), `standingBan.ts` builds a municipality's standing rules (one or several per municipality, one per activity) over its boundary from the stored copy in `data/boundaries` (see Municipal boundaries), with no network request; each municipality's file (`victoria.ts`, `oakBay.ts`, `saanich.ts`, `esquimalt.ts`, `sidney.ts`, `colwood.ts`, `viewRoyal.ts`, `metchosin.ts`, `centralSaanich.ts`, `langford.ts`, `sooke.ts`, `highlands.ts`, `northSaanich.ts`) is its config, run by the server. A rule lists its `periods` (each a permission over a yearly month-day range and/or a from/until date) and the `otherwise` permission outside them, so Langford is "by permit only" for Nov 1–30 and Mar 15–Apr 15 and "prohibited" otherwise, and a year-round ban is just `otherwise: prohibited` with no periods. North Saanich's burning season dates are approximate (the district sets the burn days yearly), and its Dean Park no-burning zone has no boundary data, so it is only in the description. Not covered: the CRD electoral areas (bylaw 4489 sets no standing ban; fire chiefs' bans arrive through the BC Wildfire Service layer), `crd.ts` fetches the Capital Regional District's areas (no CRD ban source yet)
- `hooks/useLoadStatus.ts`, `useTimedMessage.ts` — `useLoadStatus` says whether ban data is loading (stops after 30 seconds, `LOAD_TIMEOUT_MS`; the requests themselves carry on in the background and the map picks up late data) and, once loading is over, returns a message for 6 seconds if any source has no data because it failed or timed out, and not again until the set of such sources changes (so a source that timed out and then fails isn't announced twice). `useTimedMessage` holds a message that clears itself
- `hooks/useBans.ts` — runs the browser collectors (react-query) and fetches `/api/bans`, each once on page load with retries if it fails (never stale, so not again on focus or reconnect, and nothing refreshes while the page is open), and merges both; a placeholder source stands in for the server until it answers
- `hooks/useBansAt.ts` — returns the bans whose area contains the selected location, strictest permission first and broadest first within each, using `pointInGeometry` from `utils/geometry.ts` (Polygon/MultiPolygon with holes)
- `utils/` — helpers grouped by what they do, one file each:
  - `bans.ts` — works out what a ban permits on a day (`permissionAt` takes the first of its `periods` that covers the day, else `otherwise`; `currentPeriod`, `restricts`, `prohibitedFrom`), checks ban data from collectors and the `/api/bans` answer (drops malformed bans and sources, and throws, so the source counts as failed, when a result isn't a list or the answer isn't the expected shape), and says which sources failed to load
  - `geometry.ts` — point-in-area checks (Polygon/MultiPolygon with holes) and converting bans and points to GeoJSON for the map; bans become one shape per permission, each covering only where it is the strictest any ban gives (union of the permission's areas minus the union of every stricter one, with `polygon-clipping`), so overlapping bans show only their strictest colour and green shows only where nothing stricter applies
  - `classifyBan.ts` — maps free text to an `Activity`
  - `abms.ts` — fetches and parses BC administrative boundaries (regional districts, electoral areas, municipalities) into `Area`s; the app only parses (the stored municipal copy), while `scripts/fetchBoundaries.ts` and `collectors/crd.ts` fetch
  - `areas.ts` — `areasAt` (which areas contain a point) and `appliesAt` (whether a ban binds there, using its `applicability` rule)
  - `geocode.ts` — `searchPlaces`: Nominatim lookup limited to BC (see Place search)
  - `geolocation.ts` — `currentLocation`: the browser's position as a `LatLng`, with a message fit to show when it is blocked or unavailable
  - `bounds.ts` — `focusBounds`: the box containing a point and the areas of the bans covering it
  - `web.ts` — `fetchJson`: GET + JSON with timeout and abort handling, used by collectors and `useBans`
  - `logger.ts` — thin wrapper around `console.log`/`console.error`

  A helper used by one file only lives in that file (the react-query client in `components/App.tsx`).
- `types/` — every type file: `LatLng`, `Place` and `Bounds` (`geo.ts`), `FireBan`, `Period`, `Activity` and `Permission` (`ban.ts`; a `FireBan` is a rule about one activity in one area, with a permission over time, and `Permission` is `prohibited`, `by-permit-only`, `allowed-with-conditions` or `allowed`, strictest first), `SourceStatus`/`BansResponse` (`api.ts`, the shape `/api/bans` returns), `Collector` (`collector.ts`), and the declarations for CSS imports (`css.d.ts`) and the jest-dom test matchers (`matchers.d.ts`). A component's `Props` and other types used by one file only stay in that file
- `constants/` — every value used by more than one file, grouped by topic: ban levels, activities and permissions (`ban.ts`), the `/api/bans` path and load statuses (`api.ts`), the Bun server's port behind nginx and the hot dev server's port (`server.ts`; `deploy/nginx.conf` repeats the first), permission styles (label, icon, colours), activity and level labels (`banStyle.ts`), and map style/camera, fire zones URL and the `SHOW_FIRE_ZONES` flag (`map.ts`). A value used by one file only (a timeout, a collector's own URL) stays at the top of that file. `types/` holds no values: where a type lists allowed values (`BanLevel`, `BanType`, `LoadStatus`), it is derived from the list in `constants/` with a type-only import, so the two can't drift apart
- `test/` — fixtures and the `bun test` preloads set in `bunfig.toml`: `happydom.ts` (a DOM), `testingLibrary.ts` (matchers, cleanup) and `fakeMapLibre.tsx`, which replaces `react-map-gl/maplibre` in every test (MapLibre needs WebGL). The fake renders sources and layers as nested `div`s (`source-<id>`, `layer-<id>`), records the props each was given in `rendered`, `clickMap(lat, lng)` clicks the map the way MapLibre reports it, and a fake `useMap` records the camera moves (`flyTo`, `fitBounds`) in `camera`
- `bunfig.toml` — test preloads, and which env variables the dev server inlines into the page (`PUBLIC_*`)
- `.env.template` — defaults for build-time flags (`PUBLIC_EXAMPLE_BANS=false`); a local, gitignored `.env` overrides them, and a shell variable overrides both (`bun run dev` and `bun run build` load the two files with `--env-file`)
- `assets/` — favicon, source icon art, basemap style, and the Work Sans font with its licence (`fonts/`)
- `data/` — data the server builds bans from, stored in the repo with its source and licence: `boundaries/municipalities.json` (see Municipal boundaries)
- `scripts/` — development scripts run through mise, not part of the app: `fetchBoundaries.ts` (`mise run boundaries`)
- `deploy/` — `nginx.conf`, `security-headers.conf` and `start.sh`, used by the `Dockerfile` (see Deploy)

A failing source never takes the page down: a source that throws, times out, or returns malformed data is reported as failed (status `error`, no data), the other sources' bans stay on the map, and a toast and the panel say that bans may be missing. A `SourceStatus` is `pending` (loading, including retries of a failed attempt), `success` or `error` (every retry failed): browser sources take it from react-query, server sources from `banStore`, and a "BC Fire Bans server" placeholder stands in for the server's sources until it answers or after it failed. The spinner keeps spinning through retries. The page loads its data once: a source that failed after its retries stays failed until the page is reloaded. `components/App.test.tsx` checks this end to end with the fake map and `fetch` answered per URL. The test preload (`test/testingLibrary.ts`) gives the jest-dom matchers and Testing Library's query errors one-line failure messages: formatting a failed happy-dom element is slow enough that, inside `waitFor`, it holds up the app's own timers and fails timing tests on slow runners (`test/testingLibrary.test.tsx` checks this). Tests must give the same result in any order and on any machine speed (check with `bun test --randomize --seed <n>`, and each file alone). So: no real-time waits or "nothing happened in N ms" checks; use `jest.useFakeTimers()` with `jest.advanceTimersByTime` only for pure logic with no promises or React Query in the way (the store's schedule, `useTimedMessage`, `useLoadStatus`, always restored in `afterEach`); where React Query is involved, assert a settled state instead of moving a clock (a retry delay far longer than the test keeps a retry pending, a delay of 0 lets it finish) and wait only for things that must happen; read nothing from today's date (use fixed dates far in the past). Bun runs all test files in one process, so a `mock.module` in one file applies to later files too: don't use it in a test file (`App` takes its `collectors` as a prop for this reason); the one module mock, the fake MapLibre, is installed by a preload and reset after each test.

Each component's styles live in a plain CSS file next to it (`BanPanel.css`), with class names prefixed by the component name (`ban-panel-title`). CSS modules don't work in Bun 1.3.10's dev server (the class name object is never defined).

## Data

### Municipal boundaries

The 13 Capital Regional District municipalities' boundaries are stored in the repo, in `data/boundaries/municipalities.json` (about 22 KB), and the server builds the standing bans from that copy: no boundary is fetched while the app runs. They come from the BC Data Catalogue's "Municipalities - Legally Defined Administrative Areas of BC" (`WHSE_LEGAL_ADMIN_BOUNDARIES.ABMS_MUNICIPALITIES_SP`, layer 18 of the ABMS ArcGIS service), which is under the Open Government Licence – British Columbia, so storing and re-serving it is allowed with the attribution each municipality's source already shows. The combined "Legally Defined Administrative Areas of BC" dataset is Access Only, so take boundaries only from a layer whose own catalogue entry says OGL. `mise run boundaries` (`scripts/fetchBoundaries.ts`) fetches a fresh copy with the same simplification (`maxAllowableOffset=0.0005`, about 50 m), checks that all 13 came back, and writes the file one feature per line with its source, licence, query URL and fetch time; `data/boundaries/README.md` says the same. `collectors/standingBan.test.ts` checks that every server collector finds its boundary in the copy.

### Fire zones

Fire zone boundaries are not stored in the repo. `components/FireZones.tsx` gives the map a URL (`FIRE_ZONES_URL` in `constants/map.ts`) to the BC government's ArcGIS feature service, and the browser fetches it at runtime. The query asks the server to simplify the geometry (`maxAllowableOffset`), which keeps the response around 280 KB. The service allows cross-origin reads, unlike BC's WFS server. The ArcGIS copy has 31 zones (no Mid Island Fire Zone). The layer is currently off (`SHOW_FIRE_ZONES = false`) pending licensing clarification.

### Font

The app's own text uses [Work Sans](https://fonts.google.com/specimen/Work+Sans), a variable font (weights 100–900) stored in `assets/fonts/` as the Latin and Latin Extended `woff2` files Google Fonts serves, with its licence (`OFL.txt`, SIL Open Font License 1.1, no Reserved Font Name). The licence asks that copies carry the copyright notice and licence: the files carry the notice and licence URL in their metadata, `OFL.txt` sits next to them in the repo and is served at `/fonts/OFL.txt`, and the `@font-face` rules credit both. Those rules live in a `<style>` block in `web/index.html` and load the files from `/fonts/`: from a CSS file, Bun's bundler would inline fonts under 128 KB as `data:` URLs (which the CSP's `font-src 'self'` blocks) or fail to resolve `/fonts/`, while inline styles are left untouched. `bun run build:web` copies `assets/fonts` to `dist/public/fonts`, nginx serves it with a 30-day cache, and `server/dev.ts` serves it in dev. Map labels can't use it: MapLibre draws them with OpenFreeMap's Noto Sans glyphs (see Basemap).

### Basemap

The basemap style is [OSM Bright](https://github.com/openmaptiles/osm-bright-gl-style), bundled unchanged in `assets/map-style/osm-bright.json` with its licence (`osm-bright-LICENSE.md`: BSD-3 code, CC BY 4.0 design, so credit is required; it is in the source attribution in `constants/map.ts`). The original points at MapTiler and needs an API key, so `constants/map.ts` overrides three fields: the vector tile source and the font glyphs now come from OpenFreeMap (same OpenMapTiles schema, and the same Noto Sans fonts), and the source attribution is replaced with the combined credit. The sprite (icons) is still loaded from `openmaptiles.github.io`. Layers added by this app (zone labels) must use a font OpenFreeMap serves: Noto Sans Regular, Bold or Italic.

### Place search

`utils/geocode.ts` sends what the user types in the search box to OpenStreetMap's public Nominatim service (`nominatim.openstreetmap.org/search`, results limited to Canada and a box around BC). That is the only thing in the app that sends user input to a third party, so keep it to searches the user submits (no search-as-you-type: Nominatim's usage policy forbids autocomplete, allows about one request per second and wants the app identifiable, which the browser's `Referer` does). It allows cross-origin reads. If traffic grows, switch to a hosted geocoder with an API key. "My location" uses the browser's geolocation and never leaves the device; the position is only used to look up bans in the browser.

### Fire bans

Where a collector runs depends on its source's licence. Both BC ArcGIS sources (Bans and Prohibitions, and Fire Zones) are listed as **Access Only** in the BC Data Catalogue: reproduction is not permitted without written permission. So they are browser collectors: each visitor's browser fetches them directly, and the server must not fetch, store or re-serve them (this includes the example collector, which builds on the fire zone shapes). The ArcGIS item for the bans layer says Open Government Licence – British Columbia instead, which is where the panel's attribution text comes from; the conflict is unresolved. Sources whose licence allows redistribution can be server collectors.

`collectors/provincial.ts` reads the BC Wildfire Service "Bans and Prohibition Areas" ArcGIS layer. It excludes municipal and regional district bans, and the panel says so. The layer was empty (off-season) when the collector was written, so the free-text `TYPE`, `CATEGORY` and `ACCESS_PROHIBITION_DESCRIPTION` values are unverified: the card shows the source's own text and `classifyBan` falls back to `other`. Geometry is simplified server-side (`maxAllowableOffset=0.001`, about 100 m), so lookups near a boundary are approximate.

To add a source: write a `Collector` in `collectors/` that returns `FireBan[]` (reuse `fetchJson`, validate the response, skip bad features instead of throwing), then add it to `BROWSER_COLLECTORS` (`collectors/constants/browser.ts`) or `SERVER_COLLECTORS` (`collectors/constants/server.ts`) according to its licence; a server collector can set `refetchIntervalMs` for how often the server fetches it again. A browser source's host must also be added to the CSP. Server data lives in each machine's memory, so every machine fetches all server sources when it starts and then on their schedules; a machine Fly stops (`auto_stop_machines`) loses its data and fetches again when it wakes, during which `/api/bans` waits and the spinner spins, and extra machines each fetch the sources themselves. In dev, `bun --hot` re-runs `server/dev.ts` when server code changes and the earlier store's schedules keep running, so restart `mise run dev:hot` after editing server code.

Set `PUBLIC_EXAMPLE_BANS=true` (in the shell or in `.env`) when running `mise run dev`, `mise run dev:hot` or `bun run build` to add the fake example collector. The bundler replaces `process.env.PUBLIC_EXAMPLE_BANS` with its value at build time; `.env.template` sets it to `false` so it is always defined (left unset, the reference would stay in the page and fail in the browser, where there is no `process`). `collectors/constants/browser.ts` loads the example with a `require` inside an `if` on that variable, so without the flag the bundler drops the branch and the example collector is not in the bundle (checked on a production build; `polygon-clipping` stays in because `utils/geometry.ts` uses it to layer the map). Keep the `require` in that form, and don't set the variable for real production builds. `fly.toml` doesn't set it, so the deployed site has no example data and the `Dockerfile` builds with its default of `false`; to show example data on a deploy, add `[build.args]` with `PUBLIC_EXAMPLE_BANS = 'true'` to `fly.toml`.

## Deploy

nginx sits in front of the Bun API server, in one container. `Dockerfile` builds with `bun run build`, then starts from a non-root nginx image, copies in the `bun` binary, the static site (`dist/public`) and the API server (`dist/server`). `deploy/start.sh` runs both processes and exits when either one stops, so Fly restarts the machine. nginx listens on port 8080, serves the static files and proxies `/api/` to Bun on `127.0.0.1:3000`. `deploy/nginx.conf` holds per-IP rate limiting, gzip, long-lived caching for content-hashed files and the server settings; `deploy/security-headers.conf` holds the response headers incl. the CSP. Keep these in nginx rather than in `fly.toml`, so the app isn't tied to Fly. `fly.toml` configures Fly.io (`fly deploy`); CI (`.github/workflows/fly-deploy.yml`) typechecks, tests and then deploys on pushes to `main`. Its `paths-ignore` skips the whole workflow when every changed file is Markdown, `LICENSE`, `docs/`, `.claude/` or `.gitignore`; any other change runs it. The CSP allows only `self` plus `https://tiles.openfreemap.org` (tiles, fonts), `https://openmaptiles.github.io` (map icons) and `https://services6.arcgis.com` (BC Wildfire Service data, fetched by the browser) and `https://nominatim.openstreetmap.org` (place search); `Permissions-Policy` allows `geolocation` for the site itself; adding or changing a data or basemap host means updating it.

## Reading Logs

All logging goes through `utils/logger.ts`, which writes to `console` only. Server logs appear in the terminal running `mise run dev:hot`, where the browser's console output is echoed too, or `mise run dev`, which shows the container's nginx and Bun logs. In production, browser logs appear only in the browser console. To read logs, run the dev server in the background with Bash and read its output, or ask the user to paste the terminal output.

## Style

- Code is written in a minimal, functional style as much as possible
- Use logging generously
- Document each function above its definition with one plain line; don't record rationale or history in code
